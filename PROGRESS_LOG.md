# DataQuest: Analyst Career — Progress Log

> Future development must read this file first and continue from the exact next phase. Do not silently rewrite completed phases.

## Product constants

- Framework: Flutter, Android first.
- Architecture direction: clean feature-based architecture.
- State management: Riverpod.
- Offline-first: core lessons, content packs, grading and progress must work with no internet.
- Content format: versioned JSON packs so new tasks can be added without changing Dart code where possible.
- Learning loop: learn → try → fail safely → hint → explanation → retry.
- Hint rule: 3 levels; do not reveal the full solution first.
- Career ladder: Intern → Junior → Analyst → Senior → Lead → Head of Analytics.
- Company progression: e-commerce → SaaS → bank → hospital → logistics.
- Target devices: low-end Android phones, including 2 GB RAM devices.

## Phase 1 — Playable vertical slice

Status: **IMPLEMENTED — CI verification pending**

Implemented:
- Flutter app shell with Material 3 light/dark themes.
- Riverpod app state.
- Offline progress persistence with SharedPreferences.
- Career dashboard showing role, XP and company metrics.
- Data-driven JSON task loader.
- Reusable ticket model containing business context, goal, deliverable, hints, answer mode and rubric data.
- Three starter hands-on tickets:
  1. Spreadsheet net-revenue formula.
  2. SQL aggregation by marketing channel.
  3. Correlation-vs-causation executive recommendation.
- 3-level progressive hint UI.
- Auto-grading for formulas, SQL required logic and choice tasks.
- Retry after failure; hints and failed attempts reduce score rather than blocking progress.
- Correct tasks award XP and alter company metrics.
- Unit tests for formula and SQL grading.
- GitHub Actions workflow for analyze, test and Android debug APK build.

Important implementation note:
- The repository started empty.
- The standard Android wrapper is intentionally generated by `flutter create` in CI and can also be generated locally using the README command. This keeps the first source commit focused and reproducible.

## Known Phase 1 limitations

- Only three tickets exist.
- SharedPreferences is suitable for the first slice but should move to SQLite/drift when progress, attempts, spaced repetition and portfolio records become relational.
- SQL is currently simulated/graded by required query logic; a real local SQLite execution sandbox is not yet connected.
- No placement test, adaptive skill model, skill radar, Practice Gym, Daily Challenge, Boss Case, Interview Mode or Portfolio export yet.
- No cloud sync or leaderboards yet.
- No generated Android wrapper is committed yet; CI generates it before build.
