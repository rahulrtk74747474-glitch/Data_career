# DataQuest v1.5 Beta Validation Plan

## Objective

Validate whether the product is understandable, engaging and genuinely useful before scaling Play Store marketing.

## Pilot

Recruit 50–100 people actively trying to become data analysts. Include complete beginners and learners with some SQL/Excel experience.

## Core funnel

Measure install/open, onboarding route, first lesson, Analyst Desktop login, first Day-at-Work start/completion, first portfolio export, interview attempt, D1 return and D7 return.

The app stores the first retention/workday metrics locally in v1.5. For a controlled beta, aggregate exported beta JSON only with participant consent.

## Qualitative questions

Ask where users did not know what to do next, which task felt most like real analyst work, which felt like a quiz, whether mistake feedback taught them why they were wrong, whether they can repeat work without hints, whether they would show a flagship project to a recruiter, and whether they would pay.

## Stop/go signals

Do not scale paid acquisition if users cannot identify the next action, flagship completion is low because of confusion, advanced learners report excessive hand-holding, beginners cannot recover using feedback/hints, users cannot explain completed analysis, crashes/progress loss occur, or educational-review defects remain open.

## Monetization experiment

Let users experience enough of the Intern path and at least one meaningful work simulation before testing a paywall.

## Store positioning to test

**DataQuest — Become a Data Analyst by Doing the Job**

**Start as an Intern. Solve real company problems. Master SQL, Excel, Statistics, Python and Power BI. Build a portfolio. Pass interviews. Get promoted.**
